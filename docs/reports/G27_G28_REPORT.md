## Rework 1 - review REPORT_BRIEF_forge-g27review (Verdict REWORK, 1 MAJOR)

Finding: `check_entry_points` accepted a guard call anywhere in the call graph, not on every path; reviewer reproducer `publish(data, trusted)` with `if trusted: return data` / `return guard()` returned `ok=True`. Confirmed (it passed in v0.2.0 as first delivered).

Changes (commit above, `testkit/` + docs only; no schema/profile change, version stays 0.2.0 - untagged):
- **Static check strengthened** (`g27_entrypoints.py`, class `_Dominance`): the guard call must dominate every `return` and the end of the entry function on every path, via conservative AST control flow over `if`/`try`/`except`/`finally`/`with`/`for`/`while`/`match`. Not counted as a guard: one branch only, after an early return, after a swallowing `except` (handlers are analysed as if the `try` body had not run), right side of `and`/`or`, arms of a conditional expression, lambda, comprehension, loop body (may run zero times), a loop `else` that `break` can skip. `raise` ends a path as a rejection. Intra-tree helpers count only if they pass the same test (recursion/cycles do not count; a helper name with several definitions needs all of them guarded). New **required** argument `effect_calls`: a listed call before the guard is a violation. Findings carry line numbers.
- **Behavioural helper** `assert_guard_failures_rejected(cases, report=, rejects=, side_effects=)` with `EntryCase`/`DROP`: every counted non-exempt entry point needs a case (missing or unknown keys fail), the valid input must be accepted, each failing input must differ from it, must be rejected, and must leave no side effect.
- **Documentation**: module docstring, `testkit/README.md` (template with both halves, what each half cannot do), `docs/review-checklist.md` G27 item 5 (conditional bypass) and new item 6 (behavioural test; "a static check alone does not answer this item"), `CHANGELOG.md`. Statement: the static check is necessary, not sufficient.
- **Self-test**: the reviewer example now fails (`test_reviewer_conditional_bypass_fails`); 10 further bypass shapes fail, 10 correct shapes pass, effect-before-guard, fall-off-the-end, helper conditional, line-number reasons, required `effect_calls`; behavioural: safe entry passes, bypass-by-data (`trusted=True`) caught, effect-before-rejection caught, uncovered entry point fails, empty/no-op failing input fails, invalid valid input fails.
